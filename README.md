# 多端同步 MultiSync

面向 Android 手机和平板，使用 Kotlin 原生和 Miuix 界面，通过 OpenList 发布应用更新、归档软件生成的备份。**本软件不面向 Root：仅“自动安装”需要 Root，其余功能无需 Root。** 当前版本 **0.1.36**。目录浏览、下载和回读校验使用 WebDAV；上传优先使用 OpenList 原生分片会话，也可选配通用受限 SSH 上传通道访问同一服务。

## Root 说明

- **不是 Root 专用**：目录同步、版本对比、下载安装包、文件备份、配置导出/导入等**全部无需 Root**。
- **只有“自动安装（静默覆盖安装）”需要 Root**；没有 Root 时，下载完成的 APK 用系统/第三方安装器（如 InstallerX）手动安装即可。
- 局域网访问 / SSH 上传通道属于网络权限，与 Root 无关。

## 当前实现

- Miuix 概览、软件、备份、设置页面，手机底部导航与宽窗口侧边导航，独立规则编辑页面。
- 读取本机已安装应用，按名称或包名搜索，以图标、名称、版本和包名选择软件；系统应用仅展示，分包应用提示兼容限制。
- 软件版本对比：读取 OpenList 发布记录，与本机软件按包名匹配，展示本机版本、远端最新版本、兼容更新及历史发布信息；不需要先添加同步规则。
- OpenList 配置中指定软件与文件上传目录，可手动输入或通过 WebDAV 逐级选择远端目录；两个目录同时作为软件版本对比来源。
- 紧凑顶栏与应用列表、统一卡片间距，适配系统放大字体；详情页隐藏主导航，表单保存按钮固定在底部并避让键盘。
- 设置按连接、设备调度、权限、外观分组；规则常用选项直接显示，其他选项折叠，备份规则默认使用所选文件夹名称。
- 每台设备独立配置软件发布/订阅角色、APK 导出目录、备份源目录和远端路径。
- 检测安装包变更，周期检查兜底；导出已安装的单 APK，上传并回读校验后发布版本记录。
- 安装包与本地导出副本使用“软件名_版本号.apk”，例如 `示例应用_1.2.3.apk`。各版本平铺在同一软件目录，显示版本为空时使用内部版本号。同名但内容不同的文件会提示冲突并保留本地副本。旧哈希文件和 SHA 子目录记录继续可读；改名时优先校验并服务端复制已有安装包，再校验新路径并更新发布记录。
- 远端 APK 和发布记录确认后，默认清理本应用生成的导出副本，也可以按规则保留；不会删除软件的实际安装文件。
- 订阅高版本兼容 APK，下载后核对 SHA-256、包名、实际签名和版本，开启“自动安装”时经 Root 覆盖安装；未 Root 时只下载 APK，由系统/第三方安装器手动安装。
- 使用 Android 系统目录选择器持续授权备份目录；登记文件大小和修改时间，稳定等待后创建上传快照。
- 在相同目标目录按 SHA-256 去重，保留每台设备和每个原文件名的来源记录。
- 新文件与重复文件都回读远端内容校验；来源记录确认后，再检查本地内容并清理。
- Room 保存规则、文件观察状态和任务日志；网络约束、指数退避、进程重启后的幂等重试。
- 上传、下载与远端回读校验显示实际字节数、总量、百分比和平均速率；等待服务器确认单独显示，后台通知同步显示进度。
- 自动读取 OpenList 分片能力，按服务器返回的片大小上传（建议上限 10 MB）；响应丢失后查询会话，恢复已确认的分片，等待网盘处理完成。会话消失仍需完整回读 SHA 校验；旧服务保留 WebDAV 上传。
- 上传优先使用 OpenList 原生分片会话（`/api/fs/resumable`）：按服务器返回的片大小上传，逐片确认、断点续传，合并后完整回读校验；服务器不支持分片时回退为 WebDAV PUT。
- 可选配通用受限 SSH 上传通道：固定核验服务器主机密钥，仅转发至同机 OpenList 5244 端口；通道绑定指定 OpenList 地址，换站点时拒绝误用旧通道；私钥使用 Android Keystore 加密保存。
- Android Keystore 加密保存 WebDAV 密码；密码不写入项目配置。

## 软件版本对比

“软件”列表直接显示每条规则的本机版本、远端最新版本和比较结果，进入页面自动读取，可点击“刷新”重新检查。同步完成后自动更新结果，点击“版本详情”查看历史；“软件 → 版本对比”还可查看未添加规则的已安装软件。读取“设置 → OpenList 连接”中配置的软件和文件上传目录，也兼容已有软件规则指定的自定义目录。来源目录在 OpenList 配置中统一修改，保存后重新读取；启用 SSH 通道时读取版本也复用该通道。

默认仅显示远端已有发布记录的软件，可搜索应用名或包名；关闭“仅远端已有”可查看所有本机应用的匹配状态。点击软件查看远端历史版本、发布时间、发布设备、安装包大小、所在目录和 SHA-256。

比较使用 Android 内部 `versionCode`，不会把显示版本名称或上传时间当作版本大小。远端最新版本和适合本机的更新分别判断，签名不一致、Android 系统或 CPU 架构不兼容会提示原因；存在较低但兼容的更新时也会展示。

版本信息来自本应用自动发布的 `releases/*.json`；手工散放的 APK 不会自动解析。软件列表可点击“下载远端安装包”，版本详情可下载最新版本、兼容更新或指定历史版本。下载前通过系统选择器选择保存位置，默认文件名为 `软件名_版本号.apk`。任务由 WorkManager 执行，离开页面或切换应用后可继续；应用内与通知显示实际进度，可以取消下载。手动下载按设备的网络约束等待执行，与同步任务串行运行。

传输中的临时 I/O 中断最多尝试三次；重新尝试会重新确认发布记录和完整下载，文件身份与 SHA 校验失败则直接报错。Android 17（API 37）访问局域网或 SSH 回环通道需要允许本地网络访问，首次使用时申请，也可在“设置 → 局域网访问”重新授权。每次任务原子读取地址、账号、密码和 SSH 通道，避免配置修改期间混用不同连接的凭据。

下载时重新确认发布记录，核对完整文件大小和 SHA-256，再解析实际 APK 检查包名、版本、签名、最低系统版本及架构信息；通过后写入所选位置并回读校验。下载只保存安装包，随后可在文件管理器中安装。读取失败和无匹配版本分开显示，部分目录失败时保留其他目录的结果。可点击右上角刷新同时重读本机与远端版本。

## 配置备份与恢复

在“设置 → 配置备份”中导出和导入软件规则、备份规则、OpenList 连接、两处上传目录、调度及外观设置。默认包含连接凭据，需要设置至少 8 个字符的备份密码；整个备份使用 PBKDF2-HMAC-SHA256 和 AES-256-GCM 加密，密码与 SSH 私钥不会以明文写入文件。关闭“包含连接凭据”可导出普通 JSON。通过系统文件选择器保存，导出完成前回读校验文件。

导入先选择 JSON 文件；加密备份需输入导出时的密码。预览规则数量、目标目录与需要检查的项目，点击“导入并替换配置”后整体替换现有规则和同步设置。密码错误、文件损坏、格式不受支持、路径无效或规则标识重复时不修改当前配置；同步任务运行时无法导入，导入预览期间配置已变更时需重新预览。导入后按恢复的网络和周期设置重新登记定时检查，文件稳定状态从新一轮扫描开始。

当前设备标识始终保留，其他设备导入时还保留当前设备名称。目录长期授权和系统权限无法由 JSON 转移：无法访问的备份目录会暂停，APK 导出目录暂用本机默认位置，之后可以重新选择。未安装的软件、签名不一致或无法发布的分包软件规则也会暂停。无凭据的备份只在连接地址和账号相同时保留当前已保存的凭据，换连接时清除原凭据并提示重新配置。软件安装包、原软件备份文件和任务日志不包含在配置备份中。

## 上传目录配置

在“设置 → OpenList 连接”中配置“软件上传目录”和“文件上传目录”，默认分别为 `多端同步/apps` 与 `多端同步/backups`。点击输入框旁的文件夹图标，通过 WebDAV 读取远端子目录，进入目录后点击“选择当前目录”；可以返回上级、刷新、取消，也支持选择 WebDAV 根目录 `/`。输入框可直接指定尚未创建的目录，实际上传时再创建所需路径。

目录浏览使用当前表单中的地址、账号和密码；尚未保存连接也可读取，浏览或取消不会保存配置。保存连接时一并保存两处路径。

新软件规则默认跟随软件上传目录，并按应用名称创建子目录，例如 `软件目录/示例应用`；包名和签名仍用于识别与更新校验。名称中的路径分隔符等无效字符会替换，旧包名目录仍可作为版本来源。新备份规则默认跟随文件上传目录。在规则“更多选项”或“扫描选项”中可以关闭“跟随配置上传目录”并指定单独路径；更改上传目录不会搬移远端历史文件。

两个配置目录中的软件发布记录都会参与版本对比；普通备份的 `objects` 和 `records` 仓库不会被当作软件版本。

## 设备文件权限与传输进度

“设置 → 文件访问权限”可申请设备文件访问。Android 11 及以上使用系统“所有文件访问”授权，Android 10 及以下申请存储读写权限。该权限用于直接浏览 Download 等公共存储目录；其他应用私有目录仍受 Android 系统限制。

添加备份时可逐级选择设备存储目录，或点击“通过系统选择器授权目录”，只授权一个文件夹。系统目录使用实际获得的读写标志保存长期授权；仅获得读取权限时需关闭“校验后清理本地”。保存规则前会验证目录读取并尝试打开一个文件，已有规则也可点击“检查目录读取权限”。权限失效、目录查询失败和无文件会分开处理。

任务运行时，各页面顶部显示当前文件、文件序号、传输方向、字节量、百分比及平均速度，后台通知同步更新。上传写完请求体后显示“等待服务器确认”，只有收到成功响应才显示传输完成；未知下载总量时显示不定进度。回读校验也产生下载进度，传输完成不代表归档提交或安装已经完成，最终结果见任务日志。

## 首版边界

WebDAV 使用 HTTP/1.1 兼容连接，文件与记录上传后的服务器响应等待最长 10 分钟。网络响应中断、服务器 5xx 或 423 文件占用时，会尝试读取远端内容核验；仅在文件或记录完全一致时继续流程。已有损坏的客户端哈希对象会重新上传并校验，避免后续重试一直卡在同一个不完整文件。Cloudflare 等代理的服务器等待限制仍需由服务端配置解决，客户端等待时长不能解除代理限制。

- 支持单 APK，不发布 split APK；仅更新本机已安装、已确认签名的软件。签名轮换、多用户、系统应用和客户端自身更新尚未支持。
- 备份功能是**上传归档**。没有自动恢复原软件数据、远端备份浏览或下载到备份目录的功能。
- 去重范围为同一配置目标目录。没有持久化服务端上传锁，并发发现同一内容时仍可能发生冗余传输。
- 去重针对本客户端管理的 `objects` 仓库；远端以前手工上传的散文件尚未自动导入哈希索引。
- 周期最短 15 分钟，Android 可以延迟执行。首版使用 WorkManager，没有单独的 Magisk 常驻守护。
- 回读校验会产生下载流量；大文件还需要足够的本地快照暂存空间。
- 文件大小和修改时间稳定是启发式判断，不能证明任意软件不会继续写入。应选择原软件已完成写入的备份输出目录，优先使用写完后改名的备份格式。
- 上传不做字节级断点续传。失败后重新扫描、验证远端对象和记录，继续幂等处理。
- 不会把本地清理同步成远端删除；首版不自动删除远端历史内容。

## 构建

需要 JDK 21 与 Android SDK 37、Build Tools 37.0.0。依赖版本固定在 Gradle 文件中：AGP 9.4.1、Gradle 9.7.1、Kotlin 2.4.21、Miuix 0.9.4。Android 最低 API 24（Android 7.0）。

在 `local.properties` 中配置 SDK 路径，该文件不提交：

```properties
sdk.dir=C\:/Android/Sdk
```

Windows 构建与测试：

```powershell
.\gradlew.bat :core:test :app:testDebugUnitTest :app:assembleDebug
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，为调试签名，适合首轮验证。

## 首次使用

1. 安装 APK，打开“设置 → OpenList 连接”，填写完整的 WebDAV 地址，例如 `https://your-host/dav/`、账号和密码，并选择软件和文件上传目录。OpenList 账号应具有 WebDAV 读取/管理、上传和建目录所需权限。
2. 测试目录读取并点击底部“保存连接”。该测试只验证读取连接，写入和校验能力在实际归档时验证；设备名称和周期在“设备与调度”中独立设置。
   如需绕过反向代理 / Cloudflare 的请求限流，可在同页「上传通道」导入一份受限 SSH 端口转发通道 JSON 并测试。文件只包含 SSH `host`、`port`、`username`、`host_key`、`private_key` 和绑定的 `openlist_urls`。
3. （可选）若要“自动安装”更新，才在“设置 → Root 授权”授予 Root；不授予也可正常同步与下载。Android 13 及以上可开启任务通知。
4. 在软件页点击“选择软件”或右上角“+”，搜索并选择软件，名称、包名和默认远端目录会自动带入。新规则默认跟随配置的软件上传目录。发布端开启发布，接收端开启订阅和自动安装，双方使用同一软件远端目录；名称、是否跟随配置与 APK 导出目录在“更多选项”中设置。
5. 添加备份规则，用系统选择器选择原软件备份输出目录，默认跟随配置的文件上传目录。默认稳定等待 120 秒，校验后清理本地开启；名称、是否跟随配置、稳定等待与子目录开关在“扫描选项”中设置。
6. 点击“立即检查”。首次扫描只登记新文件；等待至少稳定时间后再次检查，或等待下一个周期。
7. 在概览查看上传、回读校验、提交、清理和安装的实际任务记录。默认只在 Android 判定的不限流量网络运行。

建议首先用可重新生成的小测试备份和普通单 APK 验证实际 OpenList 挂载驱动，再启用正式目录。真实备份归档和清理已在手机验证；跨设备自动安装仍需第二台设备联调。

## 远端布局

```text
软件远端目录/
  <软件名>_<版本号>.apk
  releases/<versionCode>-<SHA256>-<deviceId>.json

备份远端目录/
  objects/<SHA256 前两位>/<SHA256>/blob
  records/<deviceId>/<确定性的来源记录 ID>.json
```

备份对象以内容哈希命名，原文件名、来源设备、规则和对象位置保存在记录 JSON 中。文件内容只上传一份，不同来源仍写小体积记录。上传失败的未提交对象不会被当作完整归档：后续处理必须实际回读校验。

## 工程结构

```text
app/    Android UI、Room、凭据、目录授权、包管理、Root 与 WorkManager
core/   与 Android 解耦的 WebDAV、哈希、归档协议和版本选择
```

核心测试覆盖去重、损坏的远端文件、记录提交失败、源文件变化、清理失败重试、路径处理、XML 解析、重定向认证和版本/签名/设备兼容选择。Android 测试使用 Robolectric 验证 Miuix 页面启动与布局，不能代替真机 Root、目录供应器与实际网盘测试。

完整需求、选型与验收标准见 [项目可行性评估](项目可行性评估.md)。第三方组件许可见 `app/src/main/res/raw/open_source_licenses.txt`。
